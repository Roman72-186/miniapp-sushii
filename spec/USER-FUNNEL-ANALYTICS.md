# Воронки пользовательских переходов

## Цель

Показывать в админке, сколько уникальных сессий дошло до каждого ключевого этапа и где посетители остановились. Поведенческие события хранятся отдельно от `audit_log`.

## Воронки MVP

- `subscription`: лендинг → выбор тарифа → форма оплаты → редирект в YooKassa → подтверждённая оплата.
- `order`: каталог → первое добавление товара → корзина → оформление → отправка → созданный заказ.
- `auth`: вход → отправка телефона → запрос учётных данных → успешная проверка → завершённый вход.

Просмотры страниц записываются как `page.view`. Каждый клик, ввод, скролл и обычный GET-запрос не записываются.

## Identity

- До авторизации используется случайный UUID сессии из `sessionStorage`.
- Сессия меняется после 30 минут бездействия.
- `user_id` сервер получает только из проверенного JWT и сохраняет в виде необратимого HMAC-хеша.
- `telegram_id`, телефон и другие значения из URL/body не используются как analytics identity.

## Хранение

Отдельная таблица `analytics_events`: `event_id UNIQUE`, время сервера, сессия, анонимизированный user ID, имя события, воронка, чистый pathname, предыдущий pathname, безопасный тип клиента и JSON разрешённых метаданных. Индексы добавляются одинаково для SQLite и PostgreSQL. Retention по умолчанию — 180 дней.

## API

- `POST /api/analytics/events`: публичный same-origin ingest, batch до 20 событий, лимит размера, allowlist событий и метаданных, rate limit, идемпотентность по `event_id`.
- `GET /api/admin/funnel`: admin bearer, период 1/7/30 дней и воронка. Возвращает только агрегаты: шаги, конверсию, потери, самый большой отвал, страницы выхода и переходы.

Успешная оплата записывается сервером после проверки webhook YooKassa. Успешный заказ записывается backend после создания заказа. `analytics_session_id` передаётся в эти запросы только как UUID сессии.

## Frontend

- Route tracker отправляет только pathname без query/hash и исключает `/admin` и `/test`.
- Существующие цели Яндекс.Метрики дополнительно маппятся на смысловые внутренние этапы, но глобальные `UI_CLICK`/`NAVIGATION_CLICK` не копируются.
- В админке создаётся отдельная вкладка «Воронки», не внутри журнала действий.

## Privacy

Запрещено хранить телефон, email, имя, адрес, комментарии, токены, query/hash, raw referrer, IP, полный User-Agent и произвольный текст. Разрешены только тариф, срок, тип заказа/доставки, источник/канал/кампания и код этапа ошибки с ограниченной длиной.

## Ограничение MVP

«Остановившимися» считаются незавершённые и неактивные более 30 минут сессии. Завершённые и ещё активные сессии показываются отдельно. Отчёт предназначен для продуктовой диагностики, а не юридически значимого аудита.

## Проверка

- UUID/ротация сессии, отсутствие query/hash, дедупликация StrictMode.
- Endpoint отклоняет неизвестные события, PII, плохие UUID, превышение batch/rate limit.
- JWT identity определяется сервером; клиентский user ID игнорируется.
- Дубликат `event_id` не увеличивает конверсию.
- SQLite/PostgreSQL имеют одинаковый контракт вставки и агрегатов.
- Admin API требует токен, корректно считает нулевые шаги и не возвращает raw session IDs.
- UI покрывает loading/error/empty и отображение максимального отвала.
